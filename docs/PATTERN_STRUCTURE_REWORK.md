## 1. 为什么要单独立项

当前形态决策台已经能给出候选形态、方向倾向和交易区间，但图形表达与用户此前逐场复盘中的 1 分钟双线路径相比仍偏粗、偏抽象。审计后确认，这不是单一 UI 问题，也不是单纯缺少 1 分钟原始数据，而是四层问题叠加：

1. **展示层主动降采样**：`MAX_PUBLIC_POINTS=72`，会把较长的分钟路径压缩为最多 72 个点。例如 Aurora Gaming vs Vitality 整场原始两侧分别有 174、173 个点，页面只显示 72 个。
2. **候选延续被固定压缩为 9 点**：`MAX_FUTURE_POINTS=9`。在当前 12,852 个训练观察点中，12,099 个（94.1%）的候选未来路径恰好只有 9 个点，因此候选延续天然呈粗折线。
3. **历史观察点只在 7 个固定进度采样**：当前使用 3%、12%、25%、40%、55%、70%、85% 七个检查点，而不是每个有效分钟点都可成为观察点。
4. **形态分类是整段终局启发式标签，不是可观察片段的结构标签**：`classify_pattern.py` 先看整段价格的低点、高点、终点和若干时间阈值，再给整段打 A/B/C 标签；`primary_label()` 又只保留第一个 A/B/C 标签，多个同时存在的结构会被折叠。结果是面板里有大量 B4 直线阴跌、A3 折价修复、A2 中位 U 型，而 A5 W 型双底、A6 反弹确认、C1 中位震荡、B3 假反弹后归零等标签几乎无法作为候选主标签出现。

结论：当前候选图适合做粗筛入口，不适合作为“形态结构教材”或直接交易模板。继续增加曲线点数只能改善视觉平滑度，不能解决分类定义和片段对齐问题，因此需要独立重审。

## 3. 重审原则

### 3.1 数据分层

形态库必须固定为五层，禁止跨层偷换概念：

```text
原始分钟路径 -> 可观察片段 -> 结构签名 -> 带上下文的形态 -> 交易模板
```

- 原始分钟路径：保留真实 60 秒点、缺口、平台期和终局结算；10 分钟数据单独分层。
- 可观察片段：只包含观察时点之前的数据，记录起点、现价、进度、波动、回撤、穿越、区间位置。
- 结构签名：V/U/W、折价修复、持续压制、尾盘崩塌、死亡螺旋、假反弹、直线阴跌、震荡等拓扑特征。
- 带上下文的形态：结构签名必须附带游戏、市场层级、概率区间、比赛进度、赛制、侧别身份。
- 交易模板：只在样本量、方向率、盈亏比和失效条件通过门槛后生成。

### 3.2 形态标签改为多标签

同一段路径可以同时具备“中位 U 型”和“反弹确认”。主标签只用于排序和展示，不能再抹掉辅助标签。每个观察点至少保留：

```text
primary_shape
secondary_shapes[]
family
confidence
preconditions
invalidation
outcome_horizon
```

### 3.3 观察点改为分钟级滑窗

- 1 分钟数据按可用分钟滑动产生观察点，保存原始序列引用，不复制整条路径。
- 固定 7 个进度点只保留为轻量预览，不作为形态训练主样本。
- 同一场比赛同一段结构必须做重叠窗口去重，避免一个长比赛刷出几百个伪独立样本。

### 3.4 展示不替代原始结构

候选形态至少同时展示：

1. 观察方与对手方完整 1 分钟真实路径；
2. 50c 中轴；
3. 历史中位数路径；
4. 历史 25%–75% 区间带；
5. 3–5 个代表性正例和反例缩略图；
6. 观察点之后的真实延续，而不是只有一条压缩后的平均虚线。

平均线只能作为摘要，不能单独承担形态展示。

### P1.1 市场层级区分（2026-10-22 用户确认）

小局与整场不能只用一个形态名后直接复用同一套交易动作。两层可以共享“V 型、U 型、回撤修复、持续阴跌、尾盘急跌”等几何词汇，但必须把市场层级作为形态主键的一部分：

```text
形态主键 = 游戏 + 市场层级 + 赛制/比分状态 + 结构名称
小局示例 = LoL + 小局 + 当前局 + 中位 U 型反转
整场示例 = LoL + 整场 + 1:0 + 高位回撤修复
```

当前 1 分钟一级样本的差异：

```text
LoL：小局 196 场 / 1,056 侧 / 中位 41 分钟；整场 233 场 / 466 侧 / 中位 140 分钟。
CS2：小局 62 场 / 260 侧 / 中位 53 分钟；整场 64 场 / 128 侧 / 中位 142 分钟。
层级专属信号：尾盘急跌归零只在小局出现；整场逆袭反转只在整场出现。
频率偏移：整场持续坠落更偏整场；均势后单边碾压更偏小局。
```

因此页面必须固定拆成 `LoL 小局`、`LoL 整场`、`CS2 小局`、`CS2 整场` 四组。每个形态的样本比例只在同组内计算，禁止把整场侧数与小局侧数合成一个分母。

### P1.2 展示命名规范（2026-10-22 用户确认）

内部标签代码可以保留用于数据连接、回归和兼容旧库，但用户界面不再显示 `A1 / A2 / B1 / B4 / C2`。展示统一为：

```text
结构类型 + 中文形态名 + 小局/整场
```

当前展示名对照：

```text
极深V型反转 / 中位U型反转 / 高位回撤修复 / W型双底反转 / 深水反弹确认
持续阴跌 / 低位持续阴跌 / 假反弹后归零 / 尾盘急跌归零 / 整场持续坠落
均势后单边碾压 / 低位追赶后确立 / 热门全程压制 / 整场逆袭反转
```

新增形态时先登记中文展示名；内部代码不得进入卡片标题、案例标签、失效说明或统计文案。

### P1.3 未来比赛的三段式输入

未来形态预测必须按观察时点切分，禁止读取未来数据：

1. **赛前 0:0**：没有当前价格形态，只输出基础概率包络。输入联赛、赛制、强弱、阵容、动机、赛前价格和历史回撤分布。
2. **局中**：同时跟踪当前小局路径与整场路径，只用观察时点前的分钟点识别候选形态；输出候选结构、触发前沿和失效边界。
3. **首局后/局间**：把当前大比分、上一局末价格、下一局开盘反应和时间剩余加入条件，重新计算整场形态分布；BO3/BO5 必须单独建桶。

P1 只定义字段与展示，不输出可执行概率。进入 P4 后，才能用时间切分回测给出候选概率、入场区间、止盈区间与期望收益。
