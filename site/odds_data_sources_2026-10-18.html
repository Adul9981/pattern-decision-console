此前“超过 24 小时只能拿到 10 分钟”的判断，是接口参数用错导致的。修正后，2026 年 7、8 月的老比赛同样能回溯 60 秒点；LoL、CS2、Dota2 都成立。下面把实测证据、其他平台与数据集一次列清。

先说结论

主源不变：Polymarket CLOB `/prices-history`。请求只带 startTs / endTs / fidelity=1，不要带 interval。带了 interval=1d 就会被送进“最近 24 小时才细”的聚合路径，这才是过去误判的根因。

其他平台不是没有，而是各自缺一块：Kalshi 有官方 1 分钟 K 线但电竞盘极薄；Manifold 是 play money；Betfair 有真正的逐笔/价格阶梯历史，但要账户与付费，电竞深度也有限；The Odds API 只有 5 分钟快照；Abios / Bayes 是企业级实时数据，不公开历史。

所以当前最合理的组合是：Polymarket 1 分钟价格做主形态，Polymarket 成交 tape 做真实性与成交量校验，Kalshi / Manifold 只做低权重交叉参考，传统书商共识另用 5 分钟级数据。

已落地：一级 LoL 231/231 场、CS2 62/62 场已全部回填为真实 60s，世界赛入围赛 4 场也已完成；合计 297 个事件、1,914 个 .hires.jsonl、1,183,045 个点。Dota2 已验证可回溯，但尚未建立独立形态分区，暂不混入统计。

三、我们该怎么用

  1. 形态主数据：Polymarket CLOB 1 分钟。只传 startTs / endTs / fidelity=1；单场取结算前 8–12 小时，足够覆盖赛前与小局。
  2. 真实性校验：data-api `/trades`。看每个 1 分钟点附近有没有成交、成交量和大单方向；成交价是 last trade，不能和中间价混成一条线。
  3. 全历史研究：链上数据集。需要跨几千场、按地址/成交做微观结构时再用 `SII-WANGZJ/Polymarket_data`；日常回填走 API 更轻。
  4. 跨市场参考：Kalshi / Manifold。只回答“另一个市场怎么想”，权重低；Kalshi 电竞盘深度不足，不能单独触发交易。
  5. 传统书商共识：The Odds API 5 分钟。用于对照“博彩公司是否与 Polymarket 背离”，不用于 1 分钟形态。
  6. 新增交叉参考：Stake Odds Data API。当前可读取 LoL / CS2 / Dota2 / NBA 十进制赔率，但无已验证历史与推送，且 live 可能整盘暂停；接入定位见 2026-10-22 Stake 数据源评估。

四、口径与坑

参数
不要传 interval；传了就会掉进聚合路径。
价格含义
60s 点是服务端采样，不是“每分钟一定有成交”；无成交分钟可能沿用前值。
可成交性
CLOB 价格没有 bid/ask 与深度，不能直接当滑点/成交假设。
成交 tape
last trade 会被大单拉偏；与 CLOB 点交叉后再下结论。
Kalshi
几十张成交、1c/99c 报价，不等于真实可交易深度。
付费源
Betfair / Abios / Bayes 是账户或合同制；“看得到”不等于“有历史 API”。
落盘
1 分钟回填写 .hires.jsonl，不覆盖原 .jsonl；读取端优先 `.hires`。
